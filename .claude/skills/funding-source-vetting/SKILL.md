Register a funder as vetted only after its official page was fetched this run and it clears every SALSAV gate; a funder that fails a coded gate is registered as rejected with a reject_reason in plain words; any other rejection needs reject_kind not_a_funder or ended, because the database re-scores every other rejected row as vetted. The database scores and gates the row from the evidence sent: read `status`, `notes` and `reject_reason` of every `grants.register_source` and `grants.reverify_source` return, and report what was stored. Exact call shapes and allowed values: supabase/grants/API.md. Keep a rejected row to its name, program, url, status, reject_reason and target_id: the 18 trimmed rejections all inserted.
Gates (rubric v2, 100 points, coded in SQL; `select grants.discovery_brief()` returns the live rubric, gates and level definitions):
- Send itemized fit, never a fit_score: `fit.mission` (35), `fit.activity` (15), `fit.geography` (15), `fit.precedent` (5), each {level, why, quote, url} with a level from the rubric. `fit.mission.quote` is the funder's own words about what it funds; without it, or without a one-sentence vet_note, the row is stored as a hidden candidate.
- Rejected by code: University of Arizona eligibility `unlikely`, largest single award under USD 200,000, mission level none, or a total under 40.
- Those four are the only fit rejections (owner, 2026-11-12: "it doesn't have to be university specific, it doesn't have to reoccur"). UA counts as lead, co-applicant, partner, subawardee or research partner (STTR research institution, partner of an eligible farm, company, NGO or state agency); `unlikely` only when the rules exclude US universities in every role, silent rules are `unknown`. A closed, one-off or not-yet-announced call keeps the funder listed with cycle closed_unknown so the crawler catches the next one. Reject otherwise only a non-funder (technical assistance only, a research program, news, aggregator) with reject_kind not_a_funder, a program that ended with reject_kind ended, or a duplicate.
- Eligibility (20 points) comes from ua_eligibility: `eligible` or `eligible_with_partner` needs `evidence.eligibility.quote`, else it is stored as unknown. Invitation-only is listed in the cultivate lane, not rejected, when the fit is strong.
- Award (10 points) comes from award_max_usd, the largest single award in USD, not the program budget; `published` needs `evidence.award.quote`, else it is stored as estimated. Unknown is kept with amount_confidence unknown and a note.
- A deadline counts only when at least 14 days out; a sooner or past date is dropped, never guessed forward, and the funder stays listed. The dashboard files a call that closes sooner as "Under 14 days: disqualified", so use Show disqualified before calling it missing.
Quotes are copied without edits from the official page with `python supabase/grants/tools/fetch_text.py URL --grep "regex"` (WebFetch paraphrases); prefer the page registered as `url`, because the database re-checks each quote against the crawler's copy and flags the ones it cannot find. No quote, no claim.
Dedupe first with `grants.check_known` (any status), so a rejected source is never re-found; a `duplicate` result is final. Subagents may call the `grants.*` API listed in .claude/sql-api-funcs.txt (one SELECT per call), so each per-funder subagent runs its own check_known before vetting.
Source documents named by the user are read in full before their organizations are seeded (every slide, note, diagram and link).
The dashboard shows only vetted funders; separate open calls with a date from watch-list funders using cycle and deadline. Collected calls arrive as candidates and show on the dashboard marked Unverified until the discovery pass checks each one on its own page (program match, status, deadline): upsert_opportunity confirms it, reject_opportunity removes it.
Aggregators (Grants.gov XML extract, SAM.gov) are fetch sources, not funders: keep them out of the funders list and the change feed.
The scheduled discovery prompt lives only in supabase/grants/discovery-task.md; the scheduled-tasks SKILL.md just tells the run to read that file, so edit the repo file alone.
A vetted funder needs a tested collection source so the crawler finds its next call with no agent: write supabase/grants/collect/cfg/ID8.json per supabase/grants/COLLECT.md, run `node --experimental-strip-types supabase/grants/tools/adapter_check.mjs CONFIG_FILE`, then apply it with `grants.set_collection(..., verified true)`. Preference: official API, feed, site JSON endpoint, HTML call list (mode calls), the program page for one cycle a year (mode cycle), page watch last resort (mode page): it only flags a changed page and writes no call rows, so use it only when no calls, RFP, prize or news listing exists over plain HTTP, and name the blocker (js_only, bot_protected, login_required, no_listing_anywhere) in the note. Invitation-only, closed or one-off funders are not a reason: watch their listing with expect.min_items 0 and a zero_reason. A calls or cycle config counts as working only when the check returns real items (expect.min_items of at least 1); a zero-item pass proves nothing. Listing pages often show opening dates, not deadlines, so check one call's own page before trusting a listing-only config. A date a regex or detail page picks is a claim too: compare it with the page's own labelled timeline, since a second unlabelled block gave a false open call in the BIRD test (UPCOMING January 21, 2027); a count that passes is not proof. A date counts only when the page ties it to this program: a general timeline block, an opening date or a past round is not the deadline.
auto_vet true only when everything the source can return is a call of this funder's program (an exact program query, or a filter proved on real items); a broad agency search with a keyword filter stays auto_vet false and its calls wait as candidates. Check that each collected item belongs to the named program: a title filter on shared words (energy, water, tribal, climate) lets other programs' notices through.
Grants.gov uses a close date decades ahead (year 2070 or later) for rolling calls: that is no deadline. Two funder rows that collect the same call or watch the same page are one source: keep the better row and demote the other with the reason.
A multi-area NOFO may give one deadline per program area: a Grants.gov package close date is then not the program's deadline, so read the agency's deadlines page before storing it.
EU Funding & Tenders topic pages are JavaScript shells: query the SEDIA search API (POST https://api.tech.ec.europa.eu/search-api/prod/rest/search?apiKey=SEDIA, multipart query part {"terms":{"identifier":["TOPIC-ID"]}}) for status and deadlines, which come as a list per stage; eligibility held in an annex stays unverified unless that annex was read.
Breadth: enumerate many private endowments and foundations across each nexus topic (agrivoltaics, water-energy-food, drought, dryland farming, rural energy, workforce), not a handful of known names. The user has said the pool is too thin on NGOs and private foundations: check each bucket against coverage_min (bucket mapping in supabase/grants/API.md section C).
Seed every organization a source deck or report names, including recipients and re-granters that run their own grants, challenges or sub-awards: they are funding sources too.
Before choosing a collection source, try every channel (official API, feed, site JSON, embedded search keys, published sheets or grant portals, sitemap PDFs) and name each one tried, with its result, in the config's evidence. Before recording a page as unreachable, probe for its data: RSS or sitemap, WordPress custom post types, and XHR/JSON calls captured in the headless browser (endpoint_recon.py). For a US federal agency whose own site resets edge requests (USDA NIFA: HTTP/2 stream errors, then timeouts), POST https://api.grants.gov/v1/api/search2 with oppNum set to the exact RFA number and point the row at grants_gov; verify the hit before switching. Accept an endpoint only if its items are real open calls: a blog feed, a privacy-policy page or a token-bearing country list is not a funder.
When a listed funder's collection breaks (failing, zero or wrong items), triage it: moved page, changed markup, JavaScript, bot protection or login (look for a JSON endpoint or feed first), or program ended. Page watch only with the blocker named; demote with the reason when the program ended.
Pitfalls: a candidate review queue sorted by first_seen_at with limit 30 left 41 calls unread, two due the next day: sort by nearest deadline and count the queue first. A JSON regex word boundary must be written "\\b" in the config file, because a plain "\b" decodes to a backspace and the filter silently never matches (configError now refuses control characters). A zero-item config needs a zero_reason, and cycle must agree with the calls: open calls under cycle closed_unknown are a contradiction, so use fixed_deadline with next_deadline. A 403 from the edge function that a desktop fetch passes is a blocker to name, not a pass: read collection_state health after set_collection (stale means the last run failed), retry once, then switch to a page watch or a JSON endpoint. A failed or thin plain-HTTP or WebFetch read (JavaScript-rendered or bot-protected page) is not proof a program is live or dead, so re-read it in a real headless browser before recording it as unreachable or vetted; an aggregator snippet is not the official page, and a program page that says "to be announced" does not clear a date: check the funder's homepage card and its archived copy before a rescore clears next_deadline; a blocked page gets fetchability bot_protected and lower confidence, never guessed details; SAM.gov covers contract notices, not grants. A site whose certificate fails fetch_text.py is unverifiable: never disable TLS checks or quote a WebFetch paraphrase; leave it a candidate with the blocker named. A saved execute_sql output file wraps its JSON in an untrusted-data envelope: strip that envelope before json.loads, or the parse fails at character 0. Column names: funders have collect_verified_at (no collect_mode or collection_verified_at), and grants.discovery_log has no created_at; a wrong name fails the whole query, so check it with a one-row select first. Batch set_collection and reverify rows with the full 36-character id from the cfg file (never pad a short id with zeros or guess the rest; a run padded six that way and had to relaunch): an 8-character prefix cast to uuid fails the whole UNION ALL (22P02). After a batch, compare each adapter_config string's character and backslash counts with the local file.
