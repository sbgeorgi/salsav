Register a funder vetted only after its official page was fetched this run and it clears every SALSAV gate (`select grants.discovery_brief()` = live rubric); a funder failing a coded gate is registered rejected with a plain-words reject_reason; any other rejection needs reject_kind not_a_funder or ended. Read status, notes, reject_reason of every `grants.register_source`/`reverify_source` return and report what was stored (API.md). A rejected row keeps name, program, url, status, reject_reason, target_id.
- Send itemized fit, never fit_score: `fit.mission` (35), `activity` (15), `geography` (15), `precedent` (5), each {level, why, quote, url}. Without `fit.mission.quote` (funder's words) or a one-sentence vet_note the row is a hidden candidate.
- Only four fit rejections: UA eligibility `unlikely` (UA counts in any role; unlikely only if every role is excluded, silent = unknown), largest award under USD 200,000, mission level none, total under 40. Closed calls stay listed (closed_unknown). Otherwise reject only non-funders, ended programs or duplicates.
- Eligible/eligible_with_partner needs `evidence.eligibility.quote` else unknown; invitation-only strong fits go to the cultivate lane. Award = largest single award (award_max_usd), `published` needs `evidence.award.quote` else estimated. A deadline counts only at 14+ days out, never guessed forward.
- Quotes are verbatim from `python supabase/grants/tools/fetch_text.py URL --grep "regex"` (never WebFetch paraphrase). Dedupe first with `grants.check_known` (duplicate is final). Subagents call only the .claude/sql-api-funcs.txt `grants.*` functions (one SELECT each) and run their own check_known; they never reject or probe. The main session alone runs grants.reject_opportunity and probe_refresh/probe_result (one reason per id, then read back). Read user sources in full.
- Human locks (migration 023): a promoted funder stays listed (verdict keep only; a failing gate goes in the reverify note). A demoted funder or call stays rejected and locked: never re-listed, re-queued or re-added to targets.
- Collected calls are candidates, Unverified until checked on their own page (upsert_opportunity confirms, reject_opportunity removes); only a confirmed call sets its funder's deadline. Aggregators (Grants.gov, SAM.gov) are fetch sources, never funders. Discovery prompt: supabase/grants/discovery-task.md only (50-line reads).
- Every vetted funder needs a tested collection source: supabase/grants/collect/cfg/ID8.json per COLLECT.md, check with `node --experimental-strip-types supabase/grants/tools/adapter_check.mjs CONFIG_FILE`, apply with `grants.set_collection(..., verified true)`. Prefer API, feed, JSON, HTML list (calls), program page (cycle); page watch last, blocker named (js_only, bot_protected, login_required, no_listing_anywhere). Closed or invitation-only funders: listing watch, expect.min_items 0 plus zero_reason. Working = real items (min_items 1+); dates must tie to this program's labelled timeline (check one call's page).
- auto_vet true only when every returned item is this funder's program (no broad keyword searches). Demote duplicate rows. Grants.gov close dates 2070+ are rolling; multi-area NOFO deadlines come from the agency page. EU Funding & Tenders: POST the SEDIA search API (apiKey=SEDIA, terms.identifier); annex eligibility stays unverified unless read.
- Breadth: enumerate many private foundations per nexus topic (coverage_min, API.md section C); seed every organization a source names, re-granters included. Name every channel tried (API, feed, JSON, sitemap, endpoint_recon.py) in config evidence; NIFA resets: POST api.grants.gov/v1/api/search2 oppNum.
- Pitfalls: sort review queues by nearest deadline; JSON regex "\\b"; zero-item configs need zero_reason and cycle must match calls; a 403 is a named blocker (check collection_state, retry once); re-read failed plain-HTTP pages in a headless browser before calling them unreachable; bad-certificate sites stay candidates (never disable TLS); strip the untrusted-data envelope before json.loads; columns: collect_verified_at, discovery_log has no created_at; full 36-char ids in batches; compare adapter_config counts with the file.
