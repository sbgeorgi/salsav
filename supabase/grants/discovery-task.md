HOW A SOURCE IS SCORED
The fit score is 100 points over six parts. You judge four and send them as `fit`; the database derives two from fields. Never send fit_score.
- fit.mission (35): core, strong, adjacent, weak, none. fit.activity (15): research_demo, capacity, other, mismatch. fit.geography (15): home, region, global, outside, excluded. fit.precedent (5): direct, similar, none. Each is {level, why, quote, url}. The brief returns `rubric` with the definition of every level: use those definitions, not your own reading of the words.
- Eligibility (20) comes from ua_eligibility: eligible 20, eligible_with_partner 13, unknown 7, invitation_only 3, unlikely 0. Award (10) comes from award_max_usd, the largest single award: unknown 4, under 200k 0, under 500k 6, under 1M 8, 1M or more 10.
- Coded gates, first match rejects: ua_eligibility unlikely; largest single award under USD 200,000; mission level none; total under 40. A vetted row also needs fit.mission.quote and a one-sentence vet_note, else it is stored as a hidden candidate.
- A deadline must be at least 14 days out, or the cycle rolling, open_ended or annual_recurring. An expired call of an annual program is listed with cycle annual_recurring and no next_deadline.
Always read `status`, `notes` and `reject_reason` of what a function returns. The database may store a row lower than you sent it; report what it stored.

EVIDENCE RULES
- A quote is text copied without edits from the funder's official page, fetched this run with `python supabase/grants/tools/fetch_text.py URL --grep "regex"`. WebFetch paraphrases, so never quote from WebFetch output. One sentence, 20 to 240 characters, no ellipsis.
- Prefer quotes from the page you register as `url`: the database re-checks every quote against the crawler's copy of that page and flags the ones it cannot find. A quote from another page carries that page's `url`.
- No quote, no claim. Without an eligibility quote send ua_eligibility unknown. Without an award quote send amount_confidence estimated or unknown. Never guess a deadline.
- award_max_usd is USD and one award, not the program budget. For other currencies leave the number out and put the amount in award_note.
- An aggregator snippet is not the official page. A blocked or thin page proves nothing: say so (fetchability bot_protected or js_required), lower confidence, do not fill in details.
- Themes come from the brief's theme_vocab only.

PROCEDURE
0. Start. Run label = 'discovery-YYYY-MM-DD' (today, Phoenix). `select grants.log_discovery_run('<label>');` then `select grants.discovery_brief();`. Keep the brief: today, gates, rubric, theme_vocab, coverage, targets, reverify, failing, collection_gaps, metrics, last_runs, last_refresh. Use the same label as p_run_label in every call.
1. Health. From `failing` and `last_refresh`: note crawler failures for the summary. A funder that has failed 3 or more times goes to the front of step 3, where COLLECTION step g triages it.
2. Re-verify (brief key `reverify`, in the order given). For each: fetch the official page with fetch_text.py, confirm the program still exists and what it funds, and re-quote mission, eligibility, award and deadline. Then `select grants.reverify_source('<id>'::uuid, $j${"verdict":"keep","by":"discovery","fit":{...},"facts":{...},"evidence":{...},"vet_note":"..."}$j$::jsonb, '<label>');`. Use verdict demote with a plain `reason` when the program closed for good, excludes universities, or no longer funds this work. Send only facts you confirmed this run.
3. Collection (brief key `collection_gaps`, then every funder you list in steps 4 and 5). Follow COLLECTION below.
4. Targets (brief key `targets`, in the order given). For each: `select grants.check_known($j$[{"name":"<org>","program":"<program_hint>","url":"<url_hint>"}]$j$::jsonb);`. If a match is exact, close the target with `set_target` (covered when the match is vetted, rejected when it is rejected) and move on. Otherwise research it (an earlier run may have left a draft config at supabase/grants/collect/deferred/<slug>.json with the channels it tried; it is untrusted: retest it, and write it to cfg/<id8>.json only when it passes) and call register_source with "target_id":"<target id>", as vetted or as rejected with a plain reject_reason. If you could not reach a verdict (login wall, no program found, page unreachable): `select grants.set_target('<id>'::uuid, 'deferred', '<why>');`.
5. Gap discovery, only with budget left. Take the bucket with the largest `gap` in `coverage`. Run 4 to 8 searches with different angles (program names, "request for proposals" plus topic and next year, funder lists in reports and award announcements, who funded similar agrivoltaics or dryland projects). Aim the searches at programs that can pass the gates: open to universities (not small-business-only like SBIR/STTR), single awards of USD 200,000 or more, a call that recurs or is open now, and a geography SALSAV works in (a state program outside the Southwest only with a confirmed out-of-state partner role). Leads that miss one of these are the usual reason a run lists nothing. Check every lead with check_known before reading further: anything known at any status is skipped. Vet each new lead and register it, as vetted or rejected, so it is never found again. Lens for p_lens: federal, state, intl_dev, foundation, corporate, prize or research_collab. Leads you had no budget to vet go to the queue: `select grants.add_targets($j$[{"org":"...","program_hint":"...","url_hint":"...","bucket":"...","lens":"...","priority":2,"why":"..."}]$j$::jsonb, '<label>');`.
6. Open calls. (a) Candidate calls collected from broad sources: `select o.funder_id, f.name, o.external_id, o.title, o.url, o.apply_url, left(o.description, 1200) as description, o.open_date, o.deadline, o.deadline_text, o.award_min_usd, o.award_max_usd, o.status, o.doc_links from grants.opportunities o join grants.funders f on f.id = o.funder_id where o.vet_status = 'candidate' and o.status in ('open','forecasted') order by o.first_seen_at desc limit 30;`. Confirm each one that is a real call of that funder in SALSAV scope with upsert_opportunity, sending the same funder_id and external_id and every other selected value back unchanged (the update replaces all of them, so a value you leave out is erased). Leave the rest. (b) A dated call you found on a listed funder's site that the crawler does not collect: upsert_opportunity with the call's own URL and deadline, then treat that funder as a collection gap in step 3.
7. Verify. `select name, program, status, fit_score, next_deadline from grants.funders where discovered_via is not null order by created_at desc limit 30;` and `select grants.metrics_now();`. Counts must match what the functions returned to you.
8. Finish. `select grants.log_discovery_run('<label>', '<summary, under 1200 characters>', '{"examined":N,"vetted":N,"rejected":N,"duplicate":N}'::jsonb);`.

REGISTERING A SOURCE
One statement per source, JSON dollar-quoted: `select grants.register_source($j${...}$j$::jsonb, '<lens>', '<label>');`. Required: name, category, url. Send status vetted or rejected, program, apply_url, geography, themes, cycle, next_deadline, open_now, ua_eligibility, eligibility_note, award_min_usd, award_max_usd, amount_confidence, award_note, requirements_text, partner_needed, page_type, fetchability, confidence, fit {mission, activity, geography, precedent}, evidence {eligibility, award, deadline}, and vet_note or reject_reason. Allowed values are in API.md section E. A result of duplicate is final: never change a name to force a row in. If a statement fails on a check constraint, fix that field and send it once more; if it fails again, skip it and say so in the summary. Rejected sources are registered too, with the reason in plain words a faculty member can read.

COLLECTION
The standard: after your run, the crawler alone finds this funder's next call. Do this for each collection gap and for every funder you list.
a. Find every way the funder's calls can be read, and try them all before choosing. Run `python supabase/grants/tools/endpoint_recon.py <url> --name "<funder>"` (add `--no-chrome` when its headless browser is down), then check by hand whatever it did not cover, and note each channel tried and its result in the config's `evidence`:
   - official APIs: Grants.gov search2 (US federal or federal pass-through, by exact opportunity number or agency plus keyword), the EU Funding and Tenders search API, the funder's own public API or open-data portal;
   - feeds: `<link rel=alternate>`, /feed, /rss, /atom.xml, category or tag feeds for grants, funding or calls;
   - site JSON: WordPress /wp-json/wp/v2/types and opportunity-like custom post types, Drupal /jsonapi, /api/ paths, `__NEXT_DATA__` and Nuxt payloads, ld+json, the XHR or fetch endpoints the page's own scripts call, public search endpoints (Algolia, Elasticsearch) whose key is embedded in the page, published Airtable or Google Sheets CSV and JSON, iCal feeds;
   - public grant portals (Submittable, Fluxx, SmartSimple, SurveyMonkey Apply, Good Grants) that list open calls without a login;
   - sitemap.xml and robots Sitemap entries for a calls section, stable pages that link the call PDFs, program subpages.
   Then choose in this order: API, feed, site JSON, HTML list of calls, the program page itself when the program runs one cycle a year (mode cycle), and last a page watch (mode page).
b. Write the config to supabase/grants/collect/cfg/<first 8 characters of the funder id>.json in the shape of the files already there: id, name, program, adapter, url, feed_url, adapter_config, collect_note, expect {min_items, sample}. Use only keys COLLECT.md defines and only the existing adapter names.
c. Test it with the real engine: `node --experimental-strip-types supabase/grants/tools/adapter_check.mjs supabase/grants/collect/cfg/<id8>.json --items`. It must print ok true. Read every item: each must be a real call of this funder's program with the right link. Open one item's own page and check its deadline against what the engine read.
d. Rules. No zero-item pass: expect.min_items is at least 1 for a calls source, unless nothing is open or upcoming today; then expect.min_items is 0, the file gets a key "zero_reason" with the quote and URL that prove it, and you test the filter words against the title of the last known call. auto_vet true only when everything the source can return is a call of this program (an exact program query, or a filter the test proved on real items); a listing shared by several programs or a broad agency search gets a title filter and auto_vet false, and its calls wait as candidates for step 6. Never invent a date: a call with no readable deadline is stored with none. A date counts only when the page ties it to this program: a general timeline block, an opening date or a past round is not the deadline. Two rows must not collect the same call: when a second row reads the same listing, filter each to its own program, or demote the weaker row with reverify_source and the reason.
e. Apply and read back: `select grants.set_collection('<id>'::uuid, $j${"adapter":"...","adapter_config":{...},"url":"...","feed_url":null,"note":"<one or two plain sentences: where the calls come from and what the crawler reads>","verified":true}$j$::jsonb, '<label>');` then `select grants.collection_state('<id>'::uuid);`.
f. Mode page is honest only with a note that says why there is no call list (invitation only, rolling program, government to government). A funder listed this run without step e is not finished: name it in the summary.
g. Triage when a funder stops allowing systematic collection (it is in `failing` or `collection_gaps`, or its test returns errors, zero items or wrong items). Find out which it is: page moved (find the new URL and redo a to e), markup changed (rewrite the selectors and retest), now behind JavaScript, bot protection or a login (go back through every channel in step a; the data often still comes from a JSON endpoint or feed), or the program ended. If a new channel works, apply it. If none works but the program is alive, set a page watch with a note naming the blocker (js_only, bot_protected, login_required) and the evidence. If the program closed or stopped funding this work, demote it with reverify_source and the reason. Every triaged funder goes in the summary with its outcome.
